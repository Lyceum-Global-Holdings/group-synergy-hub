## Goal

Backfill bin allocations for every warehouse item that currently holds stock (`current_stock > 0`) but has no row in `warehouse_bin_allocations`. Use a GS1 SSCC / SAP EWM-style storage-bin naming scheme (`A##-R##-L##`).

Scope confirmed by the user:
- Only items with stock now (≈ 199 items across 6 location groups).
- One backfill operation, no future-state enforcement.
- One row in the data has `location_id IS NULL` and will be skipped (cannot place stock without a physical location). It will be reported back so it can be corrected manually.

## Bin scheme

For each `(company_id, location_id)` that needs bins:

- Code pattern: `A{aisle:02}-R{rack:02}-L{level:02}` (e.g. `A01-R01-L01`).
- Distribute items round-robin across a 1-aisle × N-rack × 5-level grid sized to fit the item count, with a small headroom (max 25 bins per location is enough for the largest group of 92 items at ≤ 4 items per bin; we'll use up to ~50 bins so each item gets its own bin where possible).
- Each bin is created in `warehouse_bins` with:
  - `bin_code` and `name` = the generated code
  - `location_id` = source location
  - `root_location_id` = same (parity rule)
  - `company_id` = source company
  - `status = 'active'`, `is_global_template = false`, `is_shared = false`, `capacity = NULL`
  - `description = 'Auto-generated GS1/SAP-EWM storage bin (backfill)'`
- Reuse: if a bin with the same `(company_id, location_id, bin_code)` already exists, reuse it instead of duplicating.

## Allocation

For each unbinned item with stock, insert one row into `warehouse_bin_allocations`:
- `warehouse_item_id`, `bin_id`, `location_id`, `company_id`
- `allocated_quantity = warehouse_items.current_stock`
- `reserved_quantity = 0`
- `available_quantity` is generated by the DB — never written (per project memory).
- `notes = 'Auto-backfill A01-R01-L01 scheme'`

Honors existing constraints:
- Bin-allocation uniqueness (one bin per item per location).
- Multi-tenant `company_id` is always set.
- Item-master fields are read, not written.

## How it runs

Single SQL migration that:
1. Computes the unbinned set per `(company_id, location_id)`.
2. Generates the needed bins via `INSERT … ON CONFLICT DO NOTHING` (keyed on `company_id, location_id, bin_code`).
3. Round-robins items into those bins and inserts allocations with `ON CONFLICT DO NOTHING` on `(warehouse_item_id, bin_id)`.
4. Returns counts: bins created, allocations created, items skipped (e.g. the one with `location_id IS NULL`).

No app code changes. No new UI. No DB enforcement trigger (per user choice).

## Verification

After the migration, this should return zero rows (or just the location-less item):

```sql
SELECT count(*) FROM warehouse_items wi
WHERE wi.current_stock > 0
  AND NOT EXISTS (
    SELECT 1 FROM warehouse_bin_allocations a
    WHERE a.warehouse_item_id = wi.id
  );
```

And `warehouse_bins` will show the new `A01-R01-L01` … codes per affected location. The Inventory and Bin Allocations pages will surface the new bins immediately via the existing realtime hooks.
